# Historie

Begriff der in der kommerziellen Nutzung von Rechentechnik verwendet wurde

Programme waren auf die Verarbeitung relativ kleiner Datenmengen ausgelegt
Dabei war schon bei der Erfassung der Daten festgelegt, welche Informationen daraus gewonnen werden sollten

Vorteile:

- kürzere Projektentwicklungszeiten, da nur spezielles Einzelproblem gelöst werden musste
- Redundanzen
	- Können zu Inkonsistenzen führen
- Mehrfachnutzung von Datenverwaltungsfunktionen nicht möglich
- Oft keine durchgängig rechnergestützte Verarbeitung möglich
- Keine Datenunabhängigkeit durch enge Kopplung von Programmen und Datenstrukturen
	- Eine Datenmenge konnte nur verarbeitet werden, wenn deren logische und physikalische Struktur bekannt war
	- Wenn Daten von mehreren Programmen verwendet wird, darf die Struktur der Daten nicht verändert werden oder alle Programme mussten an diese Änderungen angepasst werden

# Wandel

Wird heute noch oft verwendet

Ein Wandel von der [[Verarbeitungsorientierte Sicht|verarbeitungsorientierten Sicht]] zur [[Informationsorientierte Sicht|informationsorientierten Sicht]] -> Es wird ein einheitlicher Datenpool für eine Gruppe geschaffen, aus dem jeder Benutzer dieser Gruppe die benötigten Informationen erhält
[[Verarbeitungsorientierte Sicht|verarbeitungsorientierte Sicht]] hat die Bedeutung der Daten als eigenständige Ressource hervorgehoben

Merkmale: 

- Im Mittelpunkt stehen die Daten der Organisation und nicht der Funktionen
- Datenmodell einer Organisation ändert sich im Laufe der Zeit nicht wesentlich
- Datenbestand als von seiner Verwendung unabhängige Ressource zu sehen
